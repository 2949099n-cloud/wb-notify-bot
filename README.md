# wb-notify-bot

Мультитенантный Telegram-бот, который следит за заказами продавцов на Wildberries через официальный API (dev.wildberries.ru) и присылает уведомления о новых заказах, отменах и выкупах, плюс закреплённая ежедневная сводка и меню с доп. функциями (остатки по складам, настройка вида уведомлений, мьют типов событий).

Один бот обслуживает много независимых пользователей — каждый подключает свой магазин WB самостоятельно командой `/addshop`, токен хранится зашифрованным в БД (не в `.env`), пользователи не видят чужие магазины.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
pip install -r requirements.txt
copy .env.example .env
```

Заполните `.env`:
- `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather.
- `TOKEN_ENCRYPTION_KEY` — ключ шифрования WB-токенов пользователей, сгенерировать один раз: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`. Потеря ключа = потеря доступа ко всем сохранённым токенам.
- `TELEGRAM_ADMIN_CHAT_ID` — опционально, для оперативных алертов/смоук-теста (не для уведомлений пользователей).

WB-токены отдельных магазинов в `.env` больше не хранятся — пользователи подключают их сами в Telegram через `/addshop` (токен создаётся в личном кабинете продавца WB: Профиль → Настройки → Доступ к API).

## Проверка подключения

```bash
python scripts/check_connectivity.py
```

Проверяет `TOKEN_ENCRYPTION_KEY` и Telegram (`getMe` + тестовое сообщение, если задан `TELEGRAM_ADMIN_CHAT_ID`). Для ручной проверки/регистрации магазина без Telegram — `scripts/sync_cli.py register`.

## Запуск

```bash
python scripts/run_scheduler.py
```

Фоновый процесс: опрашивает WB каждые 5 минут, детектит события и рассылает
уведомления; раз в сутки обновляет карточки, рейтинги и тарифы.

Рассылка по умолчанию выключена — чтобы накопленная история не улетела в чат
разом. Включается явно, после чего уведомления приходят только о новых событиях:

```bash
python scripts/notify_cli.py start-notifying --shop-id 1
```

## Хостинг

Сервис должен работать постоянно — подходит VPS или любая машина, которая не
выключается. На локальном компьютере уведомления будут пропадать в периоды,
когда он выключен.

Развёртывание на сервере (Ubuntu + systemd, автозапуск и автоперезапуск) —
пошагово в [deploy/README.md](deploy/README.md).
